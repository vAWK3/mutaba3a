## Affected Pages/Routes
- /p/<profileId>/expenses?newExpense=1 — the new-expense drawer gains an optional Add receipt; Save creates then attaches
- /p/<profileId>/expenses?expense=<id> — where the drawer lands after a partial upload failure
- /p/<profileId>/expenses/receipts (Filed / All) — attached receipts appear at once

## Key Interactions to Verify
- Pick a PDF and a JPEG in the new-expense drawer, remove one, Save: the expense is listed and reopening it shows the kept file
- Save with no receipt behaves exactly as before
- Signed out (local mode): the same flow stores the file on this device

## Edge Cases
- A text file, an empty file, an 11 MB file, a name with a slash: refused before anything is sent
  Value: protects=client file rules in queued mode; fails_when=checkReceiptFile is skipped for multi-pick; why_new=only live mode tested; seam=none; no_claim=server-side rules (separate tests)
- An 11th file: not queued, "already has 10 receipts" shown
  Value: protects=the 10 cap in queued mode; fails_when=the cap check is dropped; why_new=queued mode is new; seam=none; no_claim=server cap
- One upload fails: the expense stays, the toast names the file, the drawer becomes the edit drawer at ?expense=<id>
  Value: protects=no lost or double expense; fails_when=failure closes the drawer or re-POSTs; why_new=new flow; seam=none; no_claim=real bucket errors (mocked)
- Close the drawer while uploading: it does not reopen later
  Value: protects=no surprise reopen; fails_when=the mounted guard is removed; why_new=new flow; seam=none; no_claim=none beyond protects
- Read-only (lapsed) profile: no Add receipt
  Value: protects=lapse gate; fails_when=readOnly is ignored in queued mode; why_new=queued mode is new; seam=none; no_claim=none beyond protects

## Critical Paths
- Record expense → add receipt → Save → receipt READY and downloadable on the new expense
  Value: protects=MUT-491 core flow; fails_when=uploads target no id or the wrong id; why_new=no create-mode spec exists; seam=none; no_claim=production bucket (FakeApi storage in QA)
