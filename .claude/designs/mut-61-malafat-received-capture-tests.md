## Affected Pages/Routes
- POST /v1/income: on a Malafat profile, Received with a linked client is accepted; Owed is refused.
- DELETE /v1/income/{id}: atomic undo; 409 once Malafat has allocated.
- GET /v1/payments, GET /v1/payments/{id}: new origin, captureSource, allocationState and projectId fields; new origin/allocationState filters; project filter rule (D2).
- GET /v1/me: per-profile `income` rules and `access.capture`.
- GET /v1/summaries/organization, GET /v1/summaries/customers/{id}: a phone payment is counted once as unallocated.

## Key Interactions to Verify
- Session on a Malafat profile records Received for a linked client, with and without a matter; the payment shows in Malafat's API list as capture + unallocated.
- The API key previews and allocates that payment; it leaves the unallocated filter and the session's undo now answers 409.
- Session undoes before allocation → payment REVERSED; repeat undo → 204.
